The objective of Phase 3 is to stream-process the native `drugbank.xml` dataset and extract only the molecular and biological fields validated during Phase 2.

The XML file is approximately 1.5 GB, so it must be processed incrementally rather than loaded into memory as a complete XML tree.

# Critical Top-Level Drug Record Rule

A major requirement of Phase 3 is to distinguish between a complete DrugBank drug record and nested XML elements that may also be named `<drug>`.

The valid molecular records are only those that satisfy the hierarchy:

```text
drugbank
   └── drug
```

Nested records such as:

```text
drug
 └── pathways
      └── pathway
           └── drugs
                └── drug
```

must not be interpreted as full DrugBank drug records.

Therefore, a candidate `<drug>` element should only be processed when:

```text
element tag = drug
AND
parent tag = drugbank
```

This prevents incomplete nested drug references from being incorrectly extracted.

The issue was detected during Phase 2 when a nested record produced:

```text
drug_name = Lepirudin
drug_id   = None
drug_type = None
```

while valid top-level records contained complete DrugBank identifiers and metadata.

---

# Streaming Strategy

The 1.5+ GB XML document should be processed using a memory-efficient streaming parser.

The workflow is:

```text
Open XML stream
      ↓
Read one completed XML element
      ↓
Check whether element is a top-level <drug>
      ↓
Process required fields
      ↓
Store extracted values
      ↓
Clear processed element
      ↓
Remove processed siblings
      ↓
Continue
```

The complete XML tree should never be constructed in memory.

Memory cleanup should occur immediately after each processed top-level drug record.

---

# Top-Level Drug Filtering

The extraction pipeline should initially focus on DrugBank records whose:

```text
type = small molecule
```

because subsequent molecular preprocessing, RDKit processing, conformer generation, and graph construction are designed primarily for discrete small-molecule structures.

Biotech records may be counted for reporting but should not enter the initial molecular graph corpus.

Conceptually:

```text
Top-Level DrugBank Drug
       ↓
Check @type
       ↓
small molecule?
       ├── YES → eligible for D_chem
       └── NO  → count and skip
```

This is an experimental inclusion rule and should be documented as such.

DrugBank target information represents curated drug-target associations.

# Phase 4 — XML-to-ML Intermediate Dataset Construction

## Objective

The objective of Phase 4 is to transform the raw structured outputs produced during Phase 3 into reusable intermediate datasets for machine-learning and downstream computational experiments.

The DrugBank XML file remains the authoritative source of the data, but the neural-network pipeline should not repeatedly scan the complete 1.5+ GB XML document during every experiment.

Instead, the workflow becomes:

```text
DrugBank XML
      ↓
One-Time Streaming Extraction
      ↓
Raw Structured Datasets
      ↓
ML Working Representation
      ↓
Repeated Model Experiments
```

This phase therefore creates the computational working layer between the original DrugBank XML dataset and the later molecular preprocessing, graph construction, and neural-network stages.

---

## Purpose of the Intermediate Representation

The native DrugBank XML document is optimized for hierarchical data storage and distribution rather than repeated machine-learning access.

Repeatedly scanning the complete XML file for every experiment would:

- increase execution time;
- repeatedly perform XML parsing;
- increase unnecessary disk I/O;
- complicate reproducibility;
- make experimentation slower;
- tightly couple later model stages to the original XML document.

Therefore, DrugBank XML should be parsed once during the extraction stage and converted into structured intermediate datasets.

The relationship should be:

```text
Authoritative Source
DrugBank XML
      ↓
Structured Extraction
      ↓
Intermediate Computational Representation
      ↓
ML Preprocessing and Modeling
```

The XML remains the source of truth.

The intermediate files are derived computational representations used by the proposed system.

---

## Input from Phase 3

Phase 4 should primarily consume the outputs generated during Phase 3:

```text
D_chem_raw
D_target_raw
phase3_extraction_summary
```

The raw molecular dataset contains molecular identity and property information.

The raw target dataset contains DrugBank drug-target and protein associations.

Phase 4 should not normally rescan `drugbank.xml`.

==================================================
9. COORDINATE EXTRACTION
==================================================

For every successfully generated molecular conformer, extract Cartesian
coordinates:

R ∈ R^(N × 3)


For atom i:

R_i = [x_i, y_i, z_i]


The coordinates should correspond exactly to the atom ordering used for
the graph node matrix X.


==================================================
10. COORDINATE CENTERING
==================================================

For the model representation, coordinates may be centered around the molecular
centroid.

Conceptually:

R_centered = R - mean(R)


This removes arbitrary global translation from the stored model coordinates.

Preserve the geometry itself; centering does not alter internal molecular
distances.


Recommended:

store/use centered coordinates for neural-network input.


==================================================
11. IMPORTANT SE(3) FEATURE SEPARATION
==================================================

Atomic feature matrix X and coordinate matrix R must remain conceptually
separate.

DO NOT place absolute:

x
y
z

coordinates inside ordinary scalar atom features X.


Instead:

X = chemical / atomic attributes

R = Cartesian coordinates


This is important for the later SE(3)-equivariant encoder.


The encoder should process geometry through R rather than treating absolute
coordinates as ordinary scalar descriptors.


==================================================
12. NODE SET V
==================================================

Each graph node represents an atom.

For the initial geometry-aware graph, an explicit and consistent atom policy
must be used.

Recommended baseline:

Use the hydrogen-explicit molecule generated for the 3-D conformer so that
the node set and coordinate matrix refer to the same molecular object.

Therefore:

V = all atoms in the hydrogen-explicit conformer


Also preserve:

heavy_atom_count
total_atom_count


This ensures:

number of graph nodes
=
number of rows in X
=
number of rows in R

Additional useful features may include:

Example conceptual atomic vector:

X_i = [
    atomic_number,
    degree,
    formal_charge,
    hybridization,
    aromaticity,
    chirality,
    hydrogen_count,
    ring_membership
]


Categorical attributes such as hybridization and chirality should later be

==================================================
14. EDGE SET E
==================================================

Edges should represent chemical bonds.

Bond types include:

single
double
triple
aromatic


For graph neural-network processing, bonds should normally be represented
bidirectionally.

For a chemical bond:

i -- j


store graph edges:

i → j
j → i


Therefore:

edge_index

should have the conventional graph representation:

shape = [2, number_of_directed_edges]


==================================================
15. EDGE ATTRIBUTES
==================================================

Recommended edge features include:

bond type
conjugation
ring membership
bond stereochemistry


For example:

single
double
triple
aromatic

is_conjugated
is_in_ring
bond_stereo


Optional geometric information such as interatomic distance can be derived
directly from R.


For bonded atoms i and j:

d_ij = ||R_i - R_j||


It is generally preferable for the geometry-aware encoder to derive distances
from coordinates rather than storing absolute spatial orientation as an
ordinary edge feature.

PHASE 9 — GEOMETRY-AWARE EQUIVARIANT MOLECULAR ENCODER


OBJECTIVE

Phase 9 constructs the geometry-aware molecular encoder that transforms each
Phase 7 molecular graph into a continuous latent molecular representation.

The input molecular graph is:

G = (V, E, X, R)

where:

V = molecular atoms

E = bidirectional chemical-bond connectivity

X = invariant atomic feature matrix

R = centered three-dimensional Cartesian coordinates


The encoder transforms:

G
↓
Geometry-aware atom representations
↓
Equivariant message passing
↓
Molecular-level representation
↓
μ and log σ²
↓
Latent representation z


The resulting latent variable belongs to the continuous molecular latent space:

z ∈ Z

==================================================

Total graph corpus:

767 molecular graphs


Primary subsets:

Training corpus   = 613 graphs

Validation corpus = 76 graphs

Test corpus       = 78 graphs

Fisher reference  = 128 graphs


The Fisher reference corpus remains reserved for later Fisher-information
estimation and EWC.

It should NOT be treated as a separate training or validation dataset.


==================================================
GRAPH INPUT
==================================================

Each Phase 7 graph contains:

graph_id

drug_id

drug_name

standardized_smiles

x

edge_index

edge_attr

pos


where:

x = node feature matrix X

edge_index = graph connectivity E

edge_attr = chemical bond attributes

pos = centered Cartesian coordinates R


From Phase 7:

node feature dimension = 21

edge feature dimension = 14


These values should be read from the Phase 7 metadata/schema rather than
silently hard-coded wherever possible.

PHASE 9 DATA FLOW
==================================================

Phase 8 Training Graphs
        ↓

        ↓

        ↓

        ↓

        ↓

==================================================
1. IMPORTANT ARCHITECTURAL DISTINCTION
==================================================

The molecular encoder should distinguish between:

INVARIANT FEATURES

and:

GEOMETRIC COORDINATES


Atomic attributes X are scalar/invariant chemical features.

Examples:

atomic number
degree
formal charge
hybridization
aromaticity
chirality
hydrogen information
ring membership


Coordinates R contain geometric information:

x-coordinate
y-coordinate
z-coordinate


Absolute Cartesian coordinates must NOT simply be concatenated into ordinary
scalar node features.


The coordinate matrix must enter the model through the geometry-aware
message-passing mechanism.


==================================================
2. INITIAL ATOM EMBEDDING
==================================================

The original Phase 7 node feature vector has dimension:

21


Map each node feature vector into the encoder hidden space:

X_i
↓
Linear / MLP projection
↓
h_i^(0)


Recommended initial hidden dimension:

HIDDEN_DIM = 64


Therefore:

h_i^(0) ∈ R^64


The initial feature projection may conceptually be:

Linear(21 → 64)
↓
SiLU
↓
Layer Normalization


The exact architecture should remain lightweight because the current
baseline corpus contains only 613 training molecules.


==================================================
3. EDGE REPRESENTATION
==================================================

Phase 7 provides:

edge_attr dimension = 14


These attributes describe chemical bonds and include information such as:

bond type
conjugation
ring membership
stereochemistry


Edge attributes should contribute to the message function.


For an edge:

i → j


the message can depend on:

h_i
h_j
edge_attr_ij
distance_ij


where:

distance_ij = ||r_i - r_j||


==================================================
4. GEOMETRIC RELATIONSHIPS
==================================================

For connected atoms i and j:

r_ij = r_i - r_j


and:

d_ij² = ||r_i - r_j||²


Relative distances are invariant to:

global translation

global rotation


Relative coordinate vectors transform consistently under spatial
transformations and can therefore support equivariant coordinate updates.


The architecture should NOT rely on absolute molecular orientation.


==================================================
5. EGNN-STYLE MESSAGE FUNCTION
==================================================

A lightweight EGNN-style interaction can be expressed conceptually as:

m_ij = φ_e(
    h_i,
    h_j,
    d_ij²,
    e_ij
)


where:

m_ij = message from atom j to atom i

h_i, h_j = node representations

d_ij² = squared interatomic distance

e_ij = bond/edge attributes

φ_e = learnable edge-message network


This allows the encoder to combine:

chemical topology

atomic properties

bond information

three-dimensional geometry


==================================================
6. COORDINATE-AWARE / EQUIVARIANT UPDATE
==================================================

To retain the intended equivariant component, coordinate information should
participate through relative coordinates.

An EGNN-style coordinate update can conceptually be written as:

r_i^(l+1)
=
r_i^(l)
+
Σ_j
(r_i^(l) - r_j^(l))
φ_x(m_ij)


where:

φ_x

produces a learned scalar coefficient.


Because the coordinate update is based on relative coordinate vectors and
learned scalar functions, the geometric state transforms consistently under
global translations and rotations.


IMPORTANT:

If coordinates are used only to calculate fixed distances and coordinates are
never updated or otherwise handled equivariantly, the architecture should be
described conservatively as:

geometry-aware / distance-aware

rather than making a stronger equivariance claim.


Therefore the implementation should explicitly preserve the equivariant
coordinate-update mechanism if the patent architecture requires it.


==================================================
7. NODE FEATURE UPDATE
==================================================

Aggregate messages arriving at atom i:

m_i = Σ_j m_ij


Then update the node representation:

h_i^(l+1)
=
φ_h(
    h_i^(l),
    m_i
)


Possible implementation:

message aggregation
↓
MLP
↓
residual connection
↓
normalization


Residual updates are recommended for training stability.


==================================================
8. NUMBER OF MESSAGE-PASSING LAYERS
==================================================

For the baseline implementation use:

2 EGNN-style message-passing layers


Conceptually:

Initial Atom Embeddings
        ↓
EGNN Layer 1
        ↓
EGNN Layer 2
        ↓
Final Atomic Representations


This preserves the lightweight architecture from the original patent
implementation while incorporating explicit three-dimensional geometry.


==================================================
9. GRAPH / MOLECULAR POOLING
==================================================

Molecules contain different numbers of atoms.

Therefore the final node representations must be converted into one
fixed-dimensional molecular representation.


Recommended baseline:

mean pooling


For molecule G:

h_G
=
(1 / |V|)
Σ_i h_i


Mean pooling is:

permutation invariant

independent of molecular atom ordering

compatible with variable graph sizes


Optional later experiments may compare:

sum pooling
attention pooling
set-based pooling


But mean pooling is sufficient for the baseline implementation.


==================================================
10. IMPORTANT INVARIANCE PROPERTY
==================================================

The internal geometric processing may be equivariant.

However, the final molecular representation should be invariant to arbitrary
global molecular orientation and translation.


Therefore:

h_G

μ

log σ²

z


should not change materially simply because the entire molecule is:

rotated

or

translated


This is an important property that should be tested computationally.


==================================================
11. LATENT PARAMETERIZATION
==================================================

From pooled molecular embedding h_G, construct two output heads:

μ = f_μ(h_G)

log σ² = f_logvar(h_G)


Recommended latent dimension from the project configuration:

LATENT_DIM = 32


Therefore:

μ ∈ R^32

log σ² ∈ R^32


==================================================
12. WHY μ AND log σ² ARE USED
==================================================

The encoder is designed as a variational molecular encoder.

Instead of mapping each molecule directly to one deterministic point, the
encoder represents the molecule as a latent probability distribution:

q(z|G)
=
N(
    μ,
    diag(σ²)
)


This provides a continuous latent molecular representation that can later be
used by the molecular decoder and candidate-generation mechanism.


==================================================
13. REPARAMETERIZATION TRICK
==================================================

During stochastic latent sampling:

σ = exp(0.5 × log σ²)


Sample:

ε ~ N(0, I)


Then:

z = μ + σ ⊙ ε


This is the reparameterization trick.


It allows gradients to propagate through the latent sampling operation during
later end-to-end training.


==================================================
14. TRAINING AND EVALUATION LATENT POLICY
==================================================

A clear policy should be used.


During stochastic training:

z = μ + σ ⊙ ε


For deterministic validation / testing / representation extraction:

z = μ


Using μ for deterministic evaluation avoids random differences between
repeated evaluations of the same molecule.


==================================================
15. LATENT DIMENSION
==================================================

Use:

LATENT_DIM = 32


This matches the project configuration established earlier.


Therefore each molecule obtains a compact representation:

z ∈ R^32


==================================================
16. FEATURE NORMALIZATION
==================================================

Some Phase 7 node attributes are continuous numerical features.

atomic mass

computed using:

TRAINING DATA ONLY

The fitted normalization parameters should then be frozen and reused for:

Categorical one-hot features should not be standardized as if they were
continuous measurements.


==================================================
17. MINI-BATCH GRAPH PROCESSING
==================================================

Molecules contain different numbers of atoms.

The encoder therefore requires graph batching.


A batch should retain:

concatenated node features

concatenated coordinates

adjusted edge indices

edge attributes

graph-membership / batch vector


The batch vector indicates which molecule each atom belongs to.


Conceptually:

batch = [
    graph 0 nodes,
    graph 1 nodes,
    graph 2 nodes,

==================================================
19. IMPORTANT PHASE BOUNDARY
==================================================

Phase 9 should define and validate the encoder architecture.


However, μ, log σ² and z do NOT automatically constitute a scientifically

A learning objective is required.


If the molecular decoder and reconstruction objective are introduced in the

Phase 9 constructed and computationally validated the encoder architecture.

Phase 10 performs the first actual representation-learning stage.


The encoder maps:

G = (V, E, X, R)

μ(G)

q(z|G)

z
=

+

=

    0.5 × log σ²
)


and:

ε ~ N(0, I)


The latent vector has dimensionality:

z ∈ R^32

==================================================

Phase 9 produced an initialized encoder capable of computing:

==================================================
1. VARIATIONAL LATENT DISTRIBUTION
==================================================

For each molecular graph G, the encoder produces:

μ(G)

and:

log σ²(G)


These define:

qφ(z|G)

=
N(
    μ(G),
    diag(σ²(G))
)


where:

φ

denotes the encoder parameters.


During training:

z
=
μ
+
σ ⊙ ε


where:

ε ~ N(0,I)


During deterministic evaluation:

z = μ


This ensures reproducible molecular embeddings for:

validation

testing

visualization

similarity analysis

later Fisher estimation.


==================================================
2. A LEARNING SIGNAL IS REQUIRED
==================================================

A variational encoder cannot learn useful molecular representations from the
KL-divergence term alone.


The model requires a reconstruction or predictive objective that forces z to
retain information about the input molecule.


Therefore Phase 10 should introduce a baseline molecular reconstruction
mechanism.


Conceptually:

Molecular Graph G
        ↓
Encoder
        ↓
μ, log σ²
        ↓
z
        ↓
Decoder / Reconstruction Heads
        ↓
Predicted Molecular Information
        ↓
Reconstruction Loss


==================================================
3. BASELINE DECODER STRATEGY
==================================================

For the first baseline implementation, the decoder does NOT need to generate a
complete chemically valid molecule yet.


Instead, lightweight reconstruction heads can be used to reconstruct meaningful
graph-level molecular descriptors or pooled structural representations.


This keeps Phase 10 focused on:

learning the baseline latent representation


rather than immediately solving the much harder problem of full molecular
generation.


Possible reconstruction targets include selected molecular-level properties
derived directly from the input graph.


Examples:

number of atoms

number of heavy atoms

number of bonds

mean node-feature representation

aggregated bond-feature representation

selected normalized structural descriptors


The exact reconstruction targets must be derived only from the existing graph
representation and should not introduce information from the validation or test
sets.


==================================================
4. WHY NOT FULL SMILES GENERATION YET
==================================================

Full molecular generation requires additional design decisions involving:

sequence decoder architecture

SMILES or SELFIES vocabulary

tokenization

sequence padding

teacher forcing

validity constraints

chemical reconstruction evaluation


Introducing all of these simultaneously with the first latent-learning stage
would make it difficult to determine whether problems originate from:

the encoder

the latent representation

or the sequence decoder.


Therefore the recommended progression is:

Phase 10
=
baseline latent representation learning


Later phase
=
full molecular decoder / candidate generation


==================================================
5. RECONSTRUCTION TARGET VECTOR
==================================================

For each molecular graph G, construct a deterministic graph-level target vector:

y_G


The target should summarize structural information already contained in the
molecular graph.


One recommended baseline is:

y_G
=
[
    mean node features,
    mean edge features,
    normalized graph-size descriptors
]


For example:

mean(X)

mean(edge_attr)

normalized number of nodes

normalized number of bonds

normalized number of heavy atoms


Because Phase 7 provides:

21 node features

14 edge features


the reconstruction target could contain approximately:

21 node-summary dimensions

+

14 edge-summary dimensions

+

3 graph-size dimensions


giving:

38 reconstruction dimensions


The exact dimension should be explicitly documented by the implementation.


==================================================
6. TRAINING-ONLY TARGET NORMALIZATION
==================================================

Any continuous graph-level reconstruction target must be normalized using
statistics derived from:

TRAINING DATA ONLY


The resulting mean and standard deviation values are then frozen and reused for:

training

validation

test


This prevents information leakage.


==================================================
7. LATENT DECODER / RECONSTRUCTION HEAD
==================================================

A lightweight decoder can map:

z ∈ R^32

to:

Conceptually:

z
↓

↓

↓
Linear
↓
Reconstructed graph-level target


Recommended baseline:

32
→

→
reconstruction dimension


This decoder is intentionally lightweight.


Its purpose is to provide a learning signal for the latent representation.


It should NOT yet be described as a molecular generator.


==================================================
8. RECONSTRUCTION LOSS
==================================================

For continuous reconstruction targets, a simple baseline objective is:

L_recon
=
MSE(
    ŷ_G,
    y_G
)


where:

ŷ_G

is the decoder prediction


and:

y_G

is the true molecular reconstruction target.


This encourages z to preserve structural information about the molecular graph.


==================================================
9. KL-DIVERGENCE REGULARIZATION
==================================================

The variational latent representation should also be regularized toward a
standard Gaussian prior:

p(z)
=
N(0,I)


The KL divergence for each molecule is:

L_KL
=
-1/2
Σ
[
    1
    +
    log σ²
    -
    μ²
    -
    exp(log σ²)
]


This prevents the latent space from becoming an arbitrary collection of
disconnected deterministic codes.


It encourages:

continuity

smoothness

sampling compatibility

latent-space regularity.


==================================================
10. TOTAL VARIATIONAL OBJECTIVE
==================================================

The baseline Phase 10 loss should combine:

reconstruction loss

and:

KL-divergence loss


Conceptually:

L_total
=
L_recon
+
β L_KL


where:

β

controls the strength of latent regularization.


For the initial experiment, a relatively small KL weight is recommended so
that reconstruction learning is not overwhelmed early in training.


For example:

BETA_KL = 0.001


This is a baseline hyperparameter and must be documented rather than treated as
a universally optimal value.


==================================================
11. KL ANNEALING
==================================================

A useful improvement is to gradually introduce KL regularization during the
first part of training.


Conceptually:

β_t
=
β_max × annealing_factor


Early epochs:

β_t ≈ 0


Later epochs:

β_t → β_max


This reduces the risk of:

posterior collapse


where the encoder ignores the molecular input and produces latent
distributions that are too close to the prior.


For the first implementation, either:

fixed small β

or:

simple linear KL warm-up


is acceptable.


If KL annealing is implemented, it must be recorded in the experiment
configuration.

7. Calculate reconstruction loss.

20. POSTERIOR-COLLAPSE CHECK
==================================================

Posterior collapse is an important risk in variational learning.


Possible warning signs include:

μ approximately zero for every molecule

log σ² approximately zero for every molecule

very small latent variance across the dataset

KL divergence approaching zero immediately

decoder reconstruction remaining poor


Therefore Phase 10 should explicitly monitor:

mean KL loss

latent variance

reconstruction loss


Posterior collapse should be reported rather than silently ignored.

==================================================

Recommended primary representation:

        ↓

SELFIES validity does NOT remove the need for chemical validation.


Every generated molecule must still be checked using a chemistry toolkit such

==================================================
2. WHY SELFIES IS PREFERRED FOR THE BASELINE
==================================================

Direct SMILES generation can fail because generated sequences may contain:

unclosed rings

invalid branches

invalid atom syntax

incorrect token combinations


SELFIES provides a more robust molecular sequence representation.


Therefore the preferred pipeline is:

z
↓
SELFIES decoder
↓
Generated SELFIES
↓
SELFIES-to-SMILES conversion
↓
RDKit molecular parsing
↓
Chemical QC


SMILES should still be stored because it is useful for:

RDKit processing

canonicalization

comparison

downstream evaluation.


==================================================
3. TOKENIZATION
==================================================

Construct the decoder vocabulary using:

TRAINING MOLECULES ONLY


Required special tokens:

<PAD>

<BOS>

<EOS>

<UNK>


where:

PAD = sequence padding

BOS = beginning of sequence

EOS = end of sequence

UNK = unknown token


SELFIES tokens should remain chemically meaningful units rather than
character-level splitting.


Example conceptual sequence:

<BOS>
[C]
[C]
[O]
<EOS>


==================================================
4. VOCABULARY LEAKAGE POLICY
==================================================

The decoder vocabulary should be built from:

training molecular sequences only.


Validation and test sequences must not be used to construct the vocabulary.


If a validation/test molecule contains an unseen token:

<UNK>

or another explicitly documented handling mechanism should be used.


This prevents sequence-vocabulary leakage.

==================================================

Determine sequence lengths using training data.

The selected value should be based on the observed training sequence
distribution rather than an arbitrary extremely large value.

number of molecules truncated


Prefer a maximum length that avoids truncating training molecules where
computationally feasible.

This is computationally manageable for the current molecular corpus.

7. LATENT CONDITIONING
==================================================

↓

↓

z
→

<BOS> T1 T2 T3 ... TN

T1 T2 T3 ... TN <EOS>

12. DECODER TRAINING PROCEDURE
==================================================

For each training molecule:

1. Retrieve drug_id.

6. Add BOS and EOS tokens.

7. Pad sequence.

8. Project latent vector into decoder hidden state.

9. Apply teacher forcing.

10. Predict next token.

11. Calculate cross-entropy loss.

12. Backpropagate through decoder.

13. Update decoder parameters.


The Phase-10 encoder remains frozen in the baseline decoder experiment.

# PHASE 13 — BASELINE KNOWLEDGE CONSOLIDATION AND FISHER INFORMATION REFERENCE CONSTRUCTION


## OBJECTIVE

Phase 13 is performed after establishment of the frozen baseline model state in Phase 12 and before the first closed-loop adaptation cycle.

Phase 12 established the complete baseline parameter state:

\[
\Theta^*
=
\{

\theta_D^*,
\theta_P^*
\}
\]

where:

\[
\theta_E^*
\]

represents the trained baseline geometry-aware molecular encoder,

\[
\theta_D^*
\]

represents the trained latent-conditioned molecular generative decoder,

and:

\[
\theta_P^*
\]

represents the trained DrugBank-grounded target-association predictor.

Phase 12 also established the fixed deterministic baseline latent representation:

\[
Z_0
\]

Phase 13 does not retrain these components.

Instead, Phase 13 estimates how important individual baseline model parameters are for preserving the previously learned DrugBank-grounded target-association task.

The primary mechanism used for this purpose is a:

**DIAGONAL EMPIRICAL FISHER INFORMATION APPROXIMATION**

The resulting parameter-importance values will later be used by Elastic Weight Consolidation, or EWC, during continual adaptation.

Conceptually:

```text

        ↓

        ↓

        ↓

        ↓

        ↓
```

==================================================
## 3. WHY A DIAGONAL FISHER APPROXIMATION IS USED
==================================================

A complete Fisher information matrix would contain covariance relationships among every pair of model parameters.

For a model containing tens of thousands of parameters, the full matrix would be computationally expensive and unnecessary for the intended EWC implementation.

Therefore Phase 13 uses a diagonal approximation.

For every model parameter element:

\[
\theta_j
\]

a single importance value is retained:

\[
F_j
\]

Thus:

```text
parameter θ1 → F1
parameter θ2 → F2
parameter θ3 → F3
...
```

Only the diagonal parameter importance values are stored.

This provides a computationally practical importance estimate suitable for later EWC regularization.


==================================================
## 4. EMPIRICAL FISHER DEFINITION
==================================================

For Fisher-reference molecule \(i\) and model parameter \(\theta_j\):

\[
g_{ij}
=
\frac{\partial \mathcal{L}_i}
{\partial \theta_j}
\]

where:

\[
\mathcal{L}_i
\]

is the baseline task loss for Fisher-reference molecule \(i\).

The diagonal empirical Fisher approximation is:

\[
F_j
=
\frac{1}{N}
\sum_{i=1}^{N}
g_{ij}^{2}
\]

or equivalently:

\[
F_j
=
\frac{1}{N}
\sum_{i=1}^{N}
\left(
\frac{\partial \mathcal{L}_i}
{\partial \theta_j}
\right)^2
\]

where:

\[
N=128
\]

for the current Fisher-reference corpus.

A relatively large:

\[
F_j
\]

means the baseline task loss is more sensitive to changes in that parameter under the defined Fisher objective and reference dataset.

A relatively small:

\[
F_j
\]

means the parameter is less strongly constrained by this particular baseline objective.

Fisher importance therefore represents:

**model-parameter importance under the defined task**

and not universal chemical or biological importance.


==================================================
## 5. FISHER INFORMATION REQUIRES A DEFINED TASK
==================================================

Fisher importance is meaningful only with respect to a specified model objective.

It is not appropriate to calculate arbitrary gradients and describe them as generic knowledge importance.

For the current system, the baseline biological objective is:

**DrugBank-grounded multi-label target-association prediction**

Therefore the Phase-13 Fisher calculation is based on the frozen Phase-12 predictor objective.


==================================================
## 6. PRIMARY FISHER OBJECTIVE
==================================================

**multi-label target-association Binary Cross Entropy with Logits**

```text

        ↓

        ↓

        ↓

        ↓

```


The baseline Fisher objective therefore preserves knowledge associated with:

```text

```

==================================================
## 17. SAMPLE-WISE FISHER ESTIMATION
==================================================

The Fisher reference is processed one molecule at a time.

Thus:

\[
B=1
\]

For each Fisher-reference molecule:

1. Zero encoder and predictor gradients.

2. Load the saved molecular graph.

3. Apply the frozen Phase-9/10 graph-feature normalization.

4. Pass the graph through the actual baseline encoder:

\[
\theta_E^*
\]

5. Extract deterministic:

\[
\mu
\]

6. Apply the frozen Phase-12 latent normalization.

7. Pass the normalized latent representation through:

\[
\theta_P^*
\]

8. Construct the 130-dimensional DrugBank target-association vector.

9. Compute:

\[
\mathcal{L}_i
=
\operatorname{BCEWithLogitsLoss}
\]

10. Backpropagate the sample loss.

11. Read the gradient for each included parameter.

12. Square the gradient immediately:

\[
g_{ij}^2
\]

13. Add the squared gradient to the Fisher accumulator.

No optimizer update occurs.

After all 128 molecules:

\[
F_j
=
\frac{F_j}{128}
\]


==================================================
## 18. CRITICAL MATHEMATICAL DISTINCTION
==================================================

The correct empirical Fisher calculation is:

\[
\frac{1}{N}
\sum_i
g_i^2
\]

The following shortcut would be incorrect:

\[
\left(
\frac{1}{N}
\sum_i
g_i
\right)^2
\]

because:

**average squared gradient**

is not equal to:

**square of average gradient**

The implementation therefore uses:

```text
individual sample gradient
↓
square gradient
↓
accumulate
↓
average after all molecules
```


==================================================
## 19. NO PARAMETER UPDATES
==================================================

An optimizer is not required for Fisher estimation.

Therefore Phase 13 does not instantiate an optimizer.

The computational sequence is:

```text
zero gradients
↓
forward pass
↓
loss calculation
↓
backward pass
↓
read gradient
↓
square gradient
↓
accumulate Fisher
↓
next molecule
```

The following operation never occurs:

```text
optimizer.step()
```

Thus Fisher estimation does not modify the baseline parameters.


==================================================
## 20. MODEL MODE DURING FISHER ESTIMATION
==================================================

The encoder and predictor operate in deterministic evaluation-compatible mode.

The Phase-12 predictor contains dropout.

Therefore the predictor is placed in:

```text

```

mode.

This prevents random dropout masks from changing the Fisher reference.

Evaluation mode does not disable gradient calculation.

Gradients are still calculated because parameter gradients remain enabled during the Fisher computation.

\lambda_{EWC}
\sum_j
F_j
(\theta_j-\theta_j^*)^2
\]

and the total future adaptation loss may be:

\[
\mathcal{L}_{total}
=
\mathcal{L}_{adapt}
+
\lambda_{EWC}
\sum_j
F_j
(\theta_j-\theta_j^*)^2
\]

where:

\[
\theta_j^*
\]

is the Phase-12 baseline parameter value,

\[
F_j
\]

is the Phase-13 Fisher importance,

\[
\theta_j
\]

is the parameter value during future adaptation,

and:

\[
\lambda_{EWC}
\]

controls the strength of baseline-knowledge preservation.

## 41. IMPORTANT INTERPRETATION

```text

molecular substructure importance

biological causality
binding affinity

therapeutic superiority
```

It represents:

**model-parameter importance under the defined baseline task and Fisher-reference corpus.**

Similarly:

\[

\]

does not establish that a parameter is universally useless.

It means that the parameter received no importance signal under this particular Fisher objective.

# PHASE 14 — LATENT-SPACE CANDIDATE GENERATION AND PROPOSAL POOL CONSTRUCTION

## OBJECTIVE

Phase 14 begins the first closed-loop discovery cycle.

The purpose of this phase is to generate genuinely new molecular proposals from the learned latent molecular representation rather than simply selecting existing DrugBank molecules as candidate placeholders.

The baseline state available before candidate generation is:

\[
K_0
=
\{
\Theta^*,
F_E,
F_P,
Z_0
\}
\]

where:

\[
\Theta^*
=
\{
\theta_E^*,
\theta_D^*,
\theta_P^*
\}
\]

and:

- \(\theta_E^*\) is the frozen baseline molecular encoder.
- \(\theta_D^*\) is the trained latent-conditioned molecular decoder.
- \(\theta_P^*\) is the baseline DrugBank-grounded target-association predictor.
- \(F_E\) and \(F_P\) are the Phase-13 Fisher importance references.
- \(Z_0\) is the baseline latent molecular representation.

Phase 14 uses the learned latent space and the trained decoder to construct a molecular candidate pool.

The main output is:

\[
C_t
=
\{
c_1,c_2,\ldots,c_n
\}
\]

for closed-loop cycle \(t\).

For the first cycle:

\[
t=1
\]


==================================================
## IMPORTANT DISTINCTION
==================================================

Candidate generation must be distinguished from candidate evaluation.

Phase 14 performs:

```text
latent proposal generation
latent perturbation
latent interpolation
latent neighborhood exploration
decoder-based molecular generation
SELFIES decoding
chemical validation
standardization
deduplication
baseline-relative novelty checking
candidate provenance recording
candidate-pool construction
```

Phase 14 does not yet perform:

```text
EWC parameter updates
encoder adaptation
predictor adaptation
Fisher recalculation
therapeutic optimization
binding-affinity prediction
clinical ranking
parameter drift
```

Candidate scoring and prioritization may occur in the next evaluation stage.


==================================================
## 1. WHY EXISTING DRUGBANK MOLECULES SHOULD NOT BE THE FINAL CANDIDATE POOL
==================================================

Existing DrugBank molecules may be useful during early debugging because they provide known valid molecular structures.

However, using existing DrugBank molecules as the final candidate pool would not demonstrate generative exploration.

The final implementation should therefore demonstrate:

\[
\text{learned latent representation}
\rightarrow
\text{new latent proposal}
\rightarrow
\theta_D^*
\rightarrow
\text{new molecular candidate}
\]

wherever computationally feasible.

DrugBank molecules remain useful as:

```text
latent seed molecules
reference molecules
novelty comparison corpus
similarity anchors
baseline controls
```

but they should not simply be relabeled as newly generated candidates.


==================================================
## 2. CANDIDATE GENERATION SOURCES
==================================================

Candidates may originate from several complementary proposal mechanisms.

Recommended mechanisms are:

### A. Latent Perturbation

For baseline latent vector:

\[
z_i
\]

generate:

\[
z_i'
=
z_i
+
\epsilon
\]

where:

\[
\epsilon
\sim
\mathcal{N}(0,\sigma^2 I)
\]

Small perturbations explore the local neighborhood around a known molecular representation.


### B. Neighborhood Sampling

Generate multiple local samples around selected seed latents:

\[
z_{i,k}
=
z_i
+
\epsilon_k
\]

for:

\[
k=1,\ldots,m
\]

This provides a local molecular neighborhood for each selected seed.


### C. Latent Interpolation

For two baseline latent vectors:

\[
z_a
\]

and:

\[
z_b
\]

construct:

\[
z(\alpha)
=
(1-\alpha)z_a
+
\alpha z_b
\]

with:

\[
0 < \alpha < 1
\]

Interpolation explores molecular representations between known regions of latent space.


### D. Prior / Latent Sampling

Samples may also be generated from a latent prior such as:

\[
z
\sim
\mathcal{N}(0,I)
\]

This is more exploratory than local perturbation.

Because the learned latent distribution may not perfectly match the theoretical prior, prior samples should be treated as exploratory proposals rather than automatically assumed to occupy chemically reliable latent regions.


### E. Decoder-Driven Stochastic Generation

For a fixed latent vector:

\[
z
\]

the decoder may generate multiple molecular sequences using stochastic token sampling.

Thus:

\[
z
\rightarrow
\theta_D^*
\rightarrow
c_1,c_2,\ldots,c_m
\]

The same latent region may therefore yield several different molecular proposals.


==================================================
## 3. RECOMMENDED FIRST-CYCLE GENERATION STRATEGY
==================================================

For the first closed-loop cycle, the most defensible candidate proposal strategy is a mixture of:

```text
local latent perturbation
+
latent interpolation
+
limited exploratory prior sampling
+
stochastic decoder sampling
```

This gives a balance between:

```text
exploitation of known chemical regions
and
exploration of new latent regions
```


==================================================
## 4. BASELINE LATENT SEEDS
==================================================

Candidate generation should begin from selected latent vectors in:

\[
Z_0
\]

Seed molecules should come only from the baseline corpus.

For each seed record:

```text
graph_id
drug_id
baseline latent vector
generation method
generation parameters
```

Seed selection should be deterministic and reproducible.

A fixed random seed should be used where random sampling is required.


==================================================
## 5. LOCAL LATENT PERTURBATION
==================================================

For each selected baseline seed:

\[
z_{\text{seed}}
\]

generate multiple perturbed vectors:

\[
z'
=
z_{\text{seed}}
+
\sigma\epsilon
\]

where:

\[
\epsilon
\sim
\mathcal{N}(0,I)
\]

The perturbation magnitude:

\[
\sigma
\]

must be explicitly recorded.

Because Phase 11 showed that larger perturbations produced larger molecular changes than smaller perturbations, Phase 14 should avoid arbitrarily large latent steps.

A practical initial perturbation schedule may contain several controlled values such as:

```text
small perturbation
moderate perturbation
exploratory perturbation
```

These should be treated as implementation parameters rather than universal scientific constants.


==================================================
## 6. LATENT INTERPOLATION
==================================================

Selected pairs of baseline latent vectors may be interpolated.

For seed pair:

\[
(z_a,z_b)
\]

generate:

\[
z_\alpha
=
(1-\alpha)z_a+\alpha z_b
\]

for selected interpolation coefficients.

Example:

\[
\alpha
\in
\{
0.25,
0.50,
0.75
\}
\]

Interpolation provenance must record:

```text
source drug A
source drug B
alpha
interpolated latent vector
```


==================================================
## 7. PRIOR SAMPLING
==================================================

Exploratory latent samples may be drawn from:

\[
\mathcal{N}(0,I)
\]

However, these samples should form only part of the candidate pool.

They should not dominate the first cycle because the learned latent manifold may differ from an ideal standard normal prior.

Prior-generated candidates should therefore be tagged as:

```text
exploratory_prior
```


==================================================
## 8. DECODER GENERATION
==================================================

Every proposed latent vector is passed through the frozen Phase-11 molecular decoder:

\[
\theta_D^*
\]

The decoder should remain unchanged in Phase 14.

The generation process is:

```text
candidate latent vector
        ↓
frozen θD*
        ↓
SELFIES token generation
        ↓
SELFIES sequence
        ↓
SMILES
        ↓
molecular candidate
```

Generation may use:

```text
temperature-controlled sampling
top-k sampling
greedy decoding for diagnostics
```

The exact generation parameters must be recorded.


==================================================
## 9. MULTIPLE MOLECULES PER LATENT
==================================================

A latent vector does not have to produce only one candidate.

For each proposed latent vector:

\[
z_i'
\]

the decoder may generate multiple stochastic sequences:

\[
c_{i,1},
c_{i,2},
\ldots,
c_{i,m}
\]

This allows molecular diversity to emerge even within a single latent neighborhood.


==================================================
## 10. SELFIES DECODING
==================================================

Generated decoder output should first be interpreted as a SELFIES sequence.

The candidate sequence must successfully convert:

\[
\text{SELFIES}
\rightarrow
\text{SMILES}
\]

Candidates that fail SELFIES decoding should be rejected and recorded as:

```text
selfies_decode_failure
```


==================================================
## 11. RDKIT PARSING
==================================================

Decoded SMILES should be parsed with RDKit.

Recommended sequence:

```text
SMILES
↓
MolFromSmiles(..., sanitize=False)
↓
SanitizeMol
```

Candidates that fail parsing or sanitization must be excluded from the valid candidate set.


==================================================
## 12. CHEMICAL STANDARDIZATION
==================================================

Successfully parsed candidates should be standardized using the same chemical-standardization principles established earlier.

Recommended steps include:

```text
RDKit Cleanup
FragmentParent
Uncharger
final sanitization
canonical SMILES
```

The standardized canonical SMILES should represent the final candidate identity used for deduplication.


==================================================
## 13. VALENCE VALIDATION
==================================================

Generated molecules should pass explicit valence/property-cache checks.

Candidates with invalid atomic valence or sanitization errors must not enter the final candidate pool.


==================================================
## 14. MODEL-FEASIBILITY HEAVY-ATOM FILTER
==================================================

Apply the existing model-feasibility range:

\[
4
\le
\text{heavy atoms}
\le
80
\]

This should continue to be described as:

**model feasibility filtering**

and not as a universal chemical-validity rule.


==================================================
## 15. DUPLICATE REMOVAL
==================================================

After canonicalization, duplicate molecules must be removed.

Two generated candidates with the same canonical standardized SMILES represent the same molecular candidate.

Therefore retain one candidate identity while preserving generation provenance where useful.

For generated candidate:

This should be described explicitly as:

**novel relative to the baseline DrugBank molecular corpus**

and not as globally novel chemistry.

## 4. WHY PHASE 15 IS REQUIRED
==================================================

A molecule may be syntactically valid but still be unsuitable for downstream computational evaluation.

For example, a candidate may have:

```text
unusual molecular size
extreme lipophilicity
extreme polarity
large formal charge
excessive flexibility
disconnected fragments
non-finite descriptor values
```

Therefore:

\[
valid
\neq
evaluation-ready
\]

Phase 15 provides an explicit eligibility gate before biological scoring.


==================================================
## 5. STRUCTURAL VALIDITY RECONFIRMATION
==================================================

For every Phase-14 novel candidate, reconfirm:

```text
canonical SMILES present
RDKit parsing successful
RDKit sanitization successful
property-cache update successful
valence representation valid
molecule contains atoms
```

These checks verify that no malformed candidate enters later evaluation.


==================================================
## 6. UNIQUENESS RECONFIRMATION
==================================================

Verify that standardized canonical SMILES remain unique.

For candidates:

\[
c_i
\]

and:

\[
c_j
\]

require:

\[
SMILES_{canonical}(c_i)
\neq
SMILES_{canonical}(c_j)
\]

for:

\[
i\neq j
\]

Duplicate identities should not be evaluated as separate candidates.


==================================================
## 7. BASELINE-RELATIVE NOVELTY RECONFIRMATION
==================================================

Retain the Phase-14 novelty definition.

Candidate:

\[
c_i
\]

is considered novel when its standardized canonical SMILES is absent from the baseline DrugBank molecular corpus.

Thus:

\[
c_i
\notin
D_{baseline}
\]

The terminology must remain:

**novel relative to the baseline DrugBank corpus**

and not:

**globally novel molecule**.


==================================================
## 8. HARD ELIGIBILITY RULES
==================================================

A candidate should be classified as chemically ineligible only for strict structural or numerical failure modes.

Recommended hard rejection conditions are:

```text
RDKit parse failure

sanitization failure

property-cache / valence failure

empty molecular structure

missing canonical SMILES

disconnected fragments remaining after Phase-14 standardization

non-finite required descriptor values

heavy atom count outside 4–80
```

These are eligibility failures rather than biological judgments.


==================================================
## 9. DISCONNECTED FRAGMENT CHECK
==================================================

For each candidate calculate:

\[
N_{fragments}
\]

using the authoritative Phase-14 canonical molecular representation.

Require:

\[
N_{fragments}=1
\]

for chemical eligibility.

If:

\[
N_{fragments}>1
\]

the candidate should be excluded and recorded as:

```text
disconnected_fragments
```

Because Phase 14 used fragment-parent standardization, such cases should normally be uncommon.


==================================================
## 10. MODEL-FEASIBILITY HEAVY-ATOM RANGE
==================================================

\[

\le
N_{heavy}
\le

\]

Candidates outside this interval are excluded from downstream evaluation.

This remains a:

**MODEL-FEASIBILITY CONSTRAINT**

and must not be presented as a universal definition of chemical validity.

## 25. HARD EXCLUSION VS SOFT FLAGGING

\[

```text

high TPSA
high HBD
high HBA

large absolute formal charge
multiple Lipinski violations
```

Soft flags remain attached to the candidate but do not automatically cause exclusion.

## 26. WHY SOFT FLAGS ARE IMPORTANT
==================================================

The molecular generator is intended to explore chemical space.

Overly aggressive rule-based exclusion could remove potentially interesting candidates before biological scoring.

Therefore the preferred strategy is:

\[

+
soft\ physicochemical\ characterization
\]

rather than:

\[
broad\ heuristic\ rejection
\]

## 4. WHY GENERATED CANDIDATES MUST BE RE-ENCODED
==================================================

Phase 14 generated candidate molecules using proposed latent vectors.

However, the latent vector used to generate a molecule should not automatically be assumed to be the final representation of the generated molecular structure.

Once a molecular structure has been generated, the structure itself should be evaluated.

Therefore each Phase-16 candidate must be passed back through the trained molecular encoder.

The correct evaluation pathway is:

```text
generated candidate molecule
        ↓
candidate molecular graph
        ↓
frozen encoder θE*
        ↓
deterministic candidate latent μcandidate
        ↓
frozen Phase-12 latent normalization
        ↓
frozen predictor θP*
        ↓
target-association relevance scores
```

This ensures that biological evaluation is based on the actual generated molecular structure rather than only on the latent proposal that produced it.

## 22. GENERAL BIOLOGICAL RELEVANCE SURROGATE
==================================================

If no single predefined therapeutic target is being optimized, summarize biological relevance using the highest predicted target-association scores.

Define:

\[

\]

\[

\]

\[

\[

\[

## 23. WHY TOP-5 MEAN IS USED
==================================================

Using only:

\[

\]

may allow one isolated high target score to dominate candidate ranking.

A top-5 mean provides a more stable aggregate of the candidate's strongest predicted target associations.

Therefore:

\[
K_B=5
\]

is used as an operational baseline choice.

It is not a universal biological constant.

## 26. MODEL UNCERTAINTY
==================================================

Candidate evaluation should include an estimate of model uncertainty.

The Phase-12 predictor contains dropout layers.

Therefore Phase 16 can use Monte Carlo dropout to produce an approximate predictive uncertainty signal.


==================================================
## 27. MC-DROPOUT CONFIGURATION
==================================================

Recommended number of stochastic predictor passes:

\[
M=30
\]

For every candidate, perform:

\[
30
\]

predictor forward passes using the same normalized latent representation.


==================================================
## 28. IMPORTANT MC-DROPOUT POLICY
==================================================

The encoder remains deterministic.

The predictor should first remain in evaluation mode.

Then only the predictor's Dropout modules should be activated.

Thus:

```text
encoder = eval()

predictor = eval()

activate predictor Dropout only

keep LayerNorm deterministic
```

This prevents unrelated training-mode behavior from contaminating uncertainty estimation.


==================================================
## 29. PREDICTIVE MEAN
==================================================

For candidate:

\[
i
\]

target:

\[
k
\]

and MC pass:

\[
m
\]

let:

\[
p_{ik}^{(m)}
\]

represent the stochastic sigmoid relevance score.

Then:

\[
\bar p_{ik}
=
\frac{1}{M}
\sum_{m=1}^{M}
p_{ik}^{(m)}
\]

is the MC-dropout predictive mean.


==================================================
## 30. TARGET-LEVEL UNCERTAINTY
==================================================

For candidate:

\[
i
\]

and target:

\[
k
\]

calculate:

\[
\sigma_{ik}
=
\sqrt{
\frac{1}{M-1}
\sum_{m=1}^{M}
\left(
p_{ik}^{(m)}
-
\bar p_{ik}
\right)^2
}
\]

This represents an approximate model-based predictive uncertainty signal.


==================================================
## 31. CANDIDATE-LEVEL UNCERTAINTY
==================================================

Using the same target classes selected in:

\[

\]

define candidate uncertainty:

\[

=
\frac{1}{5}
\sum_{k\in Top5_i}
\sigma_{ik}
\]

This gives the mean uncertainty associated with the candidate's strongest predicted target associations.


==================================================
## 32. MAXIMUM UNCERTAINTY
==================================================

Also retain:

=

\sigma_{ik}
\]

==================================================

SA is a heuristic computational synthetic-accessibility descriptor.

Lower values generally indicate easier estimated synthesis.

Higher values generally indicate more difficult estimated synthesis.

However:

\[

\]

## 40. SA UTILITY TRANSFORMATION
==================================================

Because:

```text

lower SA = favorable
```

SA should be transformed so that all primary utility components share the same optimization direction.

Using the conventional approximate SA range:

\[

\]

define:

\[

=
1
-
\frac{
SA_i-1
}{
9
}
\]

and clip to:

\[
[0,1]
\]

Therefore:

\[
SAUtility_i
=
clip
\left(
1-\frac{SA_i-1}{9},
0,
1
\right)
\]

Higher:

\[
SAUtility_i
\]

means more favorable heuristic synthetic accessibility.

## 28. MARGIN-BASED PAIRWISE FEEDBACK LOSS

\]

\[

\]

\[

\[

=

\left(

\left[

-

\right]
\right)
\]

The weighted feedback loss is:

\[
\mathcal{L}_{feedback}
=

\tilde w_{ij}
\mathcal{L}_{ij}
}{
\sum_{(i,j)}
\tilde w_{ij}
}
\]


==================================================
## 29. WHY A MARGIN IS USED
==================================================

A simple logistic ranking loss continuously rewards larger score separation.

That could lead to unnecessary score inflation even after the desired ordering is already achieved.

The margin-based formulation encourages:

```text
correct preference ordering

plus

a modest predefined separation
```

rather than unlimited score divergence.


==================================================
## 30. MARGIN INTERPRETATION
==================================================

The margin:

\[
m
\]

is a computational design parameter.

It is not:

```text
a biological effect size

a binding-affinity difference

an experimental activity threshold
```


32. WHY THIS UNCERTAINTY FORMULATION IS PREFERRED

QED and SAUtility are deterministic.


Therefore uncertainty originates from:

By calculating utility independently on each MC pass, biological uncertainty is automatically propagated through the fixed utility weight.


This avoids manually inventing a separate uncertainty scaling rule.

# Phase 23 — EWC Parameter-Preservation Mechanism

The EWC penalty should compare current parameters to the consolidated reference:

\[
L_{EWC}
=
\frac{\lambda}{2}
\sum_j
F_j
(\theta_j-\theta_j^*)^2
\]

Interpretation:

```text
Large Fj
→ parameter was important for baseline knowledge
→ strongly resist modification

Small Fj
→ parameter less important
→ greater adaptability permitted
```

This is what allows the system to balance:

```text
Adaptation
        ↕
Knowledge preservation
```

instead of simply fine-tuning until the original representation collapses.
